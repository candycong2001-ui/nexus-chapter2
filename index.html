CHAPTER II · 01  /  FROM TEAM TO ORGANIZATION

让虚拟团队， 拥有持续推进项目的能力

当一个人拥有虚拟团队，怎样让它长期协作，而不失忆、不失控、不反复重来？

拥有执行能力，不等于拥有项目能力。

CHAPTER II · 02  /  WHY IT STILL BREAKS

模型很强，项目为什么还是会乱？

模型能完成一次任务，不等于项目能跨越几十次任务稳定前进。

分类

用户常常只知道"这里不舒服"，不知道它属于 UI、Bug、重构还是产品问题。

散落

每次任务都能局部完成，但决定散落在聊天、代码和不同文档里。

失忆

新对话不了解旧背景，旧经验又可能已经过期。

代偿

项目越做越大，人开始替 Agent 记忆、分类、分工和验收。

如果最后还是由人记住一切、协调一切，我们真的获得了一支团队吗？

CHAPTER II · 03  /  THE MISSING LAYER

缺失的，不是能力；是项目层

所有人都在解决"怎么做"；很少有人把"项目怎样长期推进"做成一套可安装、可验证的章程。

我们补上的项目治理层 人机项目协作章程 意图 · 阶段 · 记忆治理 · 垂直切片 · 验收 · 授权
执行支撑层 · AGENT HARNESS 上下文装配 / 工具执行 / 任务编排 / 状态与检查点 把离散能力组织成可观察、可恢复、可控的一次运行。
能力资源层 · INTELLIGENCE & TOOLS 模型 / Agent / Skill / 工具 / MCP 提供理解、搜索、生成与操作等可调用能力。

能力决定“能做什么”；Harness 保证“怎样可靠地做”；项目章程管理为什么做、先做什么、怎样长期推进。

CHAPTER II · 04  /  THE TWO-ENGINE LOOP

两条引擎，贯穿一个项目的完整进程

项目从模糊想法走向运行演进；记忆保存跨阶段脉络，编排推动每一轮可验证交付。

项目进程 探索与定义 → 启动与规划 → 最小闭环 → 迭代交付 → 验收发布 → 运行与演进
记忆引擎 范围 · 状态 · 检索 · 激活 · 沉淀 让主 Agent 更了解你
互相反哺
编排引擎 判断 · 路由 · 委派 · 回收 · 审查 让每次执行更可验证
验证后的执行结果→记忆候选 / 更新状态→下一轮更准确的意图理解

宏观上，项目沿阶段向前；微观上，每一轮协作都经历理解 → 调用记忆 → 编排 → 执行 → 验证 → 沉淀记忆。

CHAPTER II · 05  /  MEMORY ENGINE · COALA-INSPIRED

记忆引擎：先分清“记什么、放哪里、何时调用”

记忆不是一堆聊天摘要，而是一套有边界的系统：范围决定隔离，类型决定用途，载体决定落点，冷热决定调用时机。

第一层 · 任务记忆本轮临时上下文

当前计划、假设、正在处理的材料与对话状态。

任务结束后不自动长期保存
第二层 · 项目记忆 · 一期核心当前项目的长期脉络

蓝图、架构、handoff、issue、attempt、fix、decision 与证据。

只在当前项目边界内调用
第三层 · 全局记忆稳定的协作规则

AGENTS 协议、通用 gotcha 与明确确认的长期偏好。

跨项目传播必须显式确认
现在正在做什么“正在调整首页布局” 调用：任务 / 工作记忆当前计划、假设和本轮上下文；任务结束后不自动长期保存。
复盘 issue / 失败尝试“上次这个页面很乱” 调用：项目记忆 · projectmem查 issue、attempt、fix、decision；再用当前代码、测试和截图校对。
跨项目的稳定规则“以后默认这样协作” 调用：全局记忆 / AGENTS 协议只保存明确确认的规则与 gotcha，不把项目细节带去别的项目。
判断当前事实“现在代码到底是什么状态？” 调用：外部真值层直接看代码、测试、配置和运行结果；它不是记忆，但可以推翻记忆。
冷记忆历史问题、旧决定、已知坑用户说“上次 / 之前 / 继续”或当前任务确实需要时，才做范围受限检索。
需求触发 → 筛选范围 / 可信状态 / 当前证据 →
热记忆本轮交接、计划、相关证据只把当前任务真正需要的部分带进上下文；完成后形成候选，再降温。

当前一期的核心不是“记得越多”，而是不越界、不乱召回、有证据才升温。

理论参考：CoALA：语言 Agent 的认知架构

CHAPTER II · 07  /  TWO ENGINES, ONE PROJECT

双引擎互补：一条闭环，让项目越做越懂你

记忆引擎让主 Agent 更好地理解意图；编排引擎让每次执行产生更高质量、可验证的记忆。两者互相喂养，持续推动同一个项目进程。

这就是成长飞轮的最小闭环：理解意图 → 编排执行 → 验证交付 → 记忆沉淀 → 更好的理解。

CHAPTER II · 08  /  VALUE IN MOTION

价值不是记住更多，而是下一次少问你一遍

下面把一轮协作具体跑一遍：从理解感受开始，调用相关记忆，再经过编排、执行、验证与沉淀，最后反哺下一次理解。

少重复沟通项目越做越省心
理解 调用记忆 编排 执行 验证 沉淀记忆

点击后，沿圆环依次看完六个环节和一次反哺。

理解把“页面很乱”收敛成本轮问题。
调用记忆唤醒已确认的视觉原则与历史反馈。
编排判断为体验切片，形成可观察的验收标准。
执行组织页面调查、实现与视觉验证。
验证测试、截图与用户确认共同验收。
沉淀记忆保存经过验证的项目规则。
反哺理解下一次再说“乱”，Agent 已经知道你指什么。
以前每次重新解释背景、目标和坑。
现在主 Agent 先唤醒脉络，再继续推进。

模型决定这一刻有多聪明；记忆和协议决定多年以后还剩下什么。
